# 管线优化与核验职责

## 优化范围

原生数据生成、PG 装载 / 建索引、Baseline 导出、原生执行及插桩、来源审计、Trace / 增量 Parquet 编译、参考答案准备、协议转换、客户端调度、传输、响应接收与核对均属于 benchmark 环境的优化范围。被测 index service 内部执行单列，保持原生工作负载、事务语义和确认层级。

生成侧同时报告从零生成和输入复用的不同边界：wall / CPU、峰值 RSS、峰值临时空间和必要保留产物。GNU time 不包含独立 PG daemon 的 CPU 时明确注明；逻辑字节、hardlink / reflink 共享和实际新增空间不能混算。

发送侧分别报告业务操作、逻辑成员、RPC、发送 / 完成速率、完整响应字节、核对及 drain。诊断靶端可能限速；有限前缀、空响应或无校验结果不证明真实服务的最大吞吐。预编码 / 缓存须计准备成本、额外磁盘和内存，不能只优化发送循环。

## 检查的触发条件

实现测试检查固定程序的不变量；输入验证证明本份数据或产物；运行核验处理本次执行可能出现的错误。通过测试不证明所有输入均正确，但也不能以此反复执行相同全量证明。

| 阶段 / 检查 | 检查对象和触发原因 | 执行频率与复用 | 成本 / 处理原则 |
| --- | --- | --- | --- |
| 固定来源版本、Schema、PG 参数 | 外部程序、DDL、列 / 索引定义、环境可能与配置不符 | 来源构建及数据库边界；不能仅凭代码测试推断实际 catalog | 保留；小元数据检查优先在进入重阶段前完成 |
| 原生客户端结果、SQL 错误、提交 / 回滚、会话清单 | 本次执行失败、关闭异常、访问路径或事件缺失 | 每份新采集核验一次；消费按摘要绑定复用通过的会话审计 | 数据相关核验；不能由旧运行成功替代 |
| PG index counter 与访问账本 | 插桩可能未覆盖本次实际访问路径 | 每次新采集取边界计数；账本在编译遍历中构建并对账 | 保留同遍核验，避免独立再建同一账本 |
| Baseline 与 PG 独立逐值对照 | 新导出产物是否对应声明的静止数据；同时验收导出实现 | 新共享 Baseline 完成时建立证据，后续加载复用文件身份 | 不在每次服务回放重查 PG；是否进一步减少独立回读需独立证明 |
| 全行状态审计 | Baseline、捕获变化及本次 PG 终态是否一致 | `full` 建立当前采集证明；`certified` 仅按构建和覆盖约束复用实现认证 | 大型排序 / PG / Parquet 遍历；不能把认证当作本次采集完整性证据 |
| Baseline 文件身份 | 消费的是否仍是被验证文件 | 独立 PG 验证时读取实际完整 SHA，按 device / inode、大小、纳秒 mtime 记录；发布目录及 hardlink 交接复用同一身份，失效重新计算摘要 | 不从 manifest 声称的摘要填充缓存；缓存缺失或无法保存只导致重读，调用次数不等于完整读盘次数 |
| WorkUnits 身份、顺序、源事件绑定 | 文件被替换 / 截断，或 Trace 不能绑定来源请求 | workload 预检读取目录和摘要；保留必要 firstEvent 索引，预检结束释放 | 流式解析所需字段；不能删掉目录的身份职责 |
| Trace 块 CRC、长度、键编码及逻辑 SHA | 持久输入可能损坏、替换或截断 | 目录 workload 的身份核验与解码合并；实际消费仍核验所读内容 | 不为取 SHA 单独解压一遍再解码；格式边界检查保留 |
| workload 事务 / 查询组、源索引覆盖、客户端覆盖及供应量 | 实际输入可能缺成员、缺边界或不足量 | 进入加载前完整预检；同一配置下结果绑定该输入 | 拒绝不足量，不循环 Trace 填数 |
| Baseline 索引展开及规范流摘要 | 加载的 Parquet / catalog 必须形成编译时声明的流 | 参考、服务和响应样本准备在实际加载中检查；独立 `check-replay` 仍完整消费以做检查 | 移除加载前额外的空目标 Baseline 派生 / 调度；保留数量、来源覆盖和摘要 |
| 增量 Parquet 写入行数 | 编码实现是否写出声明行数 | 常规路径核对 footer 与写入计数；逐行解码和值核对留给测试 / 独立验收 | 完整回读只数行不作为常规发布步骤 |
| 关闭后实际文件大小、超大行及可用盘 | 压缩率、数据宽度、尾文件及磁盘余量取决于本次数据 | 每个文件 / 生成流执行 | 保留上限与完成发布核验；不能因实现测试通过就推断一定满足目标 |
| 参考查询答案 | 为本份 Trace 提供完整有序 PK / version / value 期望 | 同 Trace、value 模式和二级过滤配置准备一次，供后端 / 客户端变体复用 | 未显式提供参考时现有入口会生成答案；正式实验应显式准备并传入，记录其独立成本 |
| 服务能力、绑定及确认 / Flush 层级 | 被测服务和实例状态可能不同 | 每次连接 / 运行核验 | 保留，不能通过降低确认要求来提高吞吐 |
| 响应 id、状态、分块、条数、完整摘要、全部收齐 | 被测系统、传输和并发执行是本轮检验对象 | 每次真实服务运行 | 保留；流式核对并计入完成窗口，减少复制、分配和同步 |
| 背压、超时、异步失败、结束排空 | 服务可能停止、变慢、断连或留下未完成请求 | 每次运行处理 | 失败上下文按需构造；不能取消实际期限、失败传播或排空 |
| 独立 snapshot oracle、配置组合、搬迁及恢复反例 | 编译 / 版本 / adapter 实现是否符合契约 | 相关实现变更或正式验收触发；各自为显式入口 | 不自动附加到每次性能回放；完整规模和恢复结论按各自证据范围声明 |

## 合并检查后的完成边界

新 Baseline 的 PG 逐值验证仍读取全部列、RowID 和实际文件 SHA；哈希前后文件身份必须一致。通过后将实际 SHA 缓存随 `baseline.partial` 的原子发布迁移，再交给同 inode 的 hardlink 消费者，避免发布后再完整读取同一批 Parquet。缓存不代替 PG 值核对，不改变验证 manifest；发布前文件发生变化仍须重新读取并拒绝摘要不符的输入。只写一次 / 只读复用是该身份缓存的前提，不能用它证明主动修改后又恢复文件元数据的文件可信。

`ReferenceReplay.prepare` 在接触后端前检查完整 workload 的身份、来源绑定、结构和供应量，返回预检结果及带核验的 Baseline / workload source。其初始状态只声明 workload 通过；调用方真正读完 Baseline 后，来源覆盖、数量和规范流摘要均通过才声明整个输入有效。再次读取失败会撤销该次 Baseline 完成状态。

实际加载的消耗、协议转换和发送保留在 Baseline 计时内。Baseline 核验失败时不执行该阶段的正常 Flush、不开始 workload、不发布成功报告；本次新建索引作为失败现场处理，不把部分写入当可复用的初始状态。运行中读到的 workload 也核对绑定的 SHA，预检不能成为后续输入变化的豁免。

Baseline 批量 RPC 的成员共享一个完成状态，调度器按该状态合并在途记录和回调；在途预算与完成数仍按逻辑成员计算，保留每个成员的延迟起点，超时采用批内最早期限。`pending_completion_groups` / `peak_completion_groups` 记录调度器维护的完成组数，不是逻辑成员数或通用 wire RPC 数。完整字段、输入摘要、源索引覆盖和响应状态核验不因完成状态合并而省略。

`check-replay` 的用途仍是独立核验，因此会完整消费 Baseline；它的空目标操作数和时间不能当作 index service 执行结果。裸文件测试入口只检查其声明的格式和供应，不能替代目录级来源证明。

`verify-service` 核验已经加载的索引：完整 workload 预检、参考 sidecar 身份、服务持久绑定、最终发布水位和逐查询结果仍须通过；它不重新派生未参与本次操作的 Baseline Parquet。其 `preflight` 仅声明 workload 身份与供应通过，索引状态由服务绑定 / 水位 / 结果核对证明。独立 oracle 的参考模型在实际加载时使用带核验的 Baseline source，Parquet 行历史及派生探针仍独立检查。

## 验证优化

每批改动固定比较构建、同一输入、有效配置和完整核对；分开测量去掉重复遍历、改变数据表示及减少调度成本的效果。小输入覆盖故意错误结果、有效但错误的输入身份、消费者中途失败、事务 / 查询组和超时；受控规模比较补充 CPU / RSS 与波动。完整三来源验收按受影响边界复用或重建，不以短测替代。
